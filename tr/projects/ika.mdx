## 1. Genel Bakış

Bu proje, T3 Gemstone O1 kartının tek başına - ayrı bir mikrodenetleyici veya
otopilot kartı olmadan - bir insansız kara aracını (İKA) baştan sona
çalıştırabildiğini gösteren açık kaynaklı bir örnektir. Motor sürücü,
ultrasonik sensör, kamera ve lidar gibi tüm donanım, Gemstone'un GPIO ve
çevre birimleri üzerinden doğrudan ROS 2 (Humble) node'larıyla sürülüyor.

Bu sayfa hem mimariye genel bir bakış sunar hem de aynı projeyi baştan nasıl
kuracağınızı adım adım anlatır. Tam kod ve kapsamlı dokümantasyon için sayfa
sonundaki Yararlı Bağlantılar bölümüne bakabilirsiniz.

## 2. Donanım Bağlantıları

| Bileşen | Arayüz | Not |
|---|---|---|
| IMU (ICM-20948) | SPI (`/dev/spidev0.3`) | Karta lehimli, dahili — ek kablo gerekmez |
| Lidar (RPLIDAR A1M8) | USB | CP2102 USB-Seri çipi üzerinden |
| Kamera (opsiyonel) | CSI0 / CSI1 | IMX219 / OV5640 gibi modülleri destekler |
| Motor Sürücü | GPIO yön + PWM hız (`libgpiod` + sysfs PWM) | Örnekte L298N kullanıldı, başka bir sürücü de kullanılabilir |
| Ultrasonik Sensörler (opsiyonel) | GPIO (`libgpiod`) | Trig/Echo çifti başına iki hat |

Dahili IMU, SPI0 arayüzü üzerinden GPIO7, GPIO8, GPIO9, GPIO10 ve GPIO11 pinlerini kullanır; bu beş
pin motor veya ultrasonik bağlantıları için kullanılmamalıdır. GPIO chip/line keşfi ve genel
kullanım için [GPIO](/tr/boards/o1/peripherals/gpio) sayfasına, IMU hakkında daha fazla bilgi için
[IMU](/tr/boards/o1/peripherals/imu) sayfasına bakabilirsiniz. Projeye özel tam pin haritası (line
numaraları, fiziksel pin karşılıkları, PWM kanalları ve 40-pin header diyagramı) dokümantasyon
reposunda ayrıntılı olarak yer alır.

## 3. Yazılım Mimarisi

Her donanım/görev kendi bağımsız ROS 2 paketinde yaşar; standart ROS mesaj tipleri (`sensor_msgs`,
`geometry_msgs`, `nav_msgs`) kullanıldığı için `teleop_twist_keyboard`, `rqt`, Nav2 ve
`slam_toolbox` gibi hazır araçlar ek bir remap yapılmadan doğrudan çalışır.

| Paket | Görev |
|---|---|
| `gemstone_imu` | IMU sürücüsü, `imu/data_raw` yayını |
| `gemstone_motor_driver` | GPIO+PWM üzerinden motor kontrolü (`cmd_vel` dinler), ve IMU tabanlı `motion_state_node` (`motion_state/odom` yayını) |
| `gemstone_ultrasonic` | Ultrasonik mesafe sensörleri, `ultrasonicN/range` yayını |
| `gemstone_camera` | Kamera sürücüsü, `camera/image_raw` yayını |
| `gemstone_image_proc` | Görüntü işleme, `camera/image_processed` yayını |
| `gemstone_lidar_bringup` | Lidar + `rf2o` odometri + SLAM/Nav2 entegrasyonu |
| `gemstone_obstacle_avoidance` | Lidar verisine dayalı güvenlik/karar katmanı |
| `gemstone_exploration_demo` | Lidar + `motion_state` tabanlı otonom keşif (durum makineli ve basit eşik tabanlı iki alternatif) |
| `gemstone_sim` | Donanımsız Gazebo simülasyonu |
| `gemstone_bringup` | URDF, parametre dosyaları ve tüm sistemi birleştiren master launch |

## 5. Bu Projeyi Kurmak

Aşağıdaki adımlar, bu projeyi kendi Gemstone O1 kartınızda baştan kurup
çalıştırmanızı anlatır. Motor sürücüsü olarak burada **L298N** kullanılıyor;
farklı bir sürücünüz varsa bağlantıları kendi sürücünüzün pin mantığına göre
uyarlamanız yeterli.

<Steps>
  <Step title="Yazılımı çekin">
    Ana kod reposunu klonlayın:

    ```bash
    git clone https://github.com/alihaydarsucu/t3gemstone-bumin-ika.git
    cd t3gemstone-bumin-ika
    ```

    - 1x pil, 1x switch (pil hattını kesmek için)
    - 1x RPLIDAR A1M8

## 7. Otonom Haritalama

İKA projesindeki donanım ve yazılım altyapısı kullanılarak, robotun
insansız olarak bir ev ortamını keşfedip haritasını çıkarması
sağlanabilir. Tüm otonom haritalama mevcut sensörlerle (lidar + IMU)
yapılabilir, ek donanım gerekmez.

### 7.1. Nasıl Çalışır?

Sistem üç katmandan oluşur: algılama (SLAM + lidar), navigasyon (Nav2 +
engelden kaçınma) ve keşif (frontier algoritması).

```mermaid
flowchart TB
    subgraph PERCEPTION["Algılama"]
        SLAM["slam_toolbox\n(Haritalama)"]
        RF2O["rf2o\n(Odometri)"]
        LIDAR["RPLIDAR A1M8\n(Lidar)"]
    end

    subgraph NAVIGATION["Navigasyon"]
        NAV2["Nav2\n(Planlama + Kontrol)"]
        AVOID["obstacle_avoidance\n(Güvenlik)"]
    end

    subgraph EXPLORATION["Keşif"]
        FRONTIER["frontier_explorer\n(Keşif Algoritması)"]
        GCS["GCS\n(Tarayıcı Arayüzü)"]
    end

    LIDAR -->|"/scan"| SLAM
    LIDAR -->|"/scan"| RF2O
    LIDAR -->|"/scan"| AVOID
    SLAM -->|"/map"| FRONTIER
    RF2O -->|"odom TF"| FRONTIER
    FRONTIER -->|"NavigateToPose"| NAV2
    NAV2 -->|"cmd_vel_nav"| AVOID
    AVOID -->|"cmd_vel"| MOTOR["Motor Sürücü"]
    GCS -->|"start/stop"| FRONTIER
```

Adım adım akış: lidar tarama yapar → harita oluşur → `frontier_explorer`
bilinmeyen sınırları (frontier) tespit eder → en uygun frontier'a Nav2 ile
hedef gönderilir → robot gider, harita güncellenir → tekrarlanır → kapsam
%99'u aşınca otomatik durur.

Algoritma, frontier'ları utility fonksiyonuyla puanlandırır: büyük
frontier'lar tercih edilir, robota uzak olanlar cezalandırır, aynı
hedefe tekrar tekrar gitme önlenir. Tespit periyodu, küme boyutu ve
ağırlıklar `frontier_explorer.yaml` üzerinden ayarlanabilir (bölüm 7.3).

### 7.2. Çalıştırma

**Simülasyonda** (donanım gerekmez):

```bash
cd /ros_ws && source /opt/ros/humble/setup.bash
colcon build --symlink-install \
  --packages-select gemstone_sim gemstone_frontier_explorer \
  gemstone_lidar_bringup gemstone_obstacle_avoidance
source install/setup.bash

ros2 launch gemstone_frontier_explorer auto_mapping.launch.py
```

Robot `house.world` içinde otomatik olarak dolaşmaya başlar. RViz ile
görsel izleme için `enable_rviz:=true` ekleyin.

<img src="/images/ika/gazebo-sim-screenshot.png" alt="Gazebo simülasyonunda otonom haritalama" />

**Gerçek donanımda**: tek fark `use_sim_time:=false`:

```bash
ros2 launch gemstone_bringup bringup.launch.py \
  enable_lidar_stack:=true enable_slam_toolbox:=true enable_nav2:=true

ros2 launch gemstone_frontier_explorer auto_mapping.launch.py \
  use_sim_time:=false
```

**Keşif kontrolü** ROS 2 servisleri ile yapılır:

```bash
ros2 service call /exploration/start std_srvs/srv/Trigger    # başlat
ros2 service call /exploration/stop std_srvs/srv/Trigger     # durdur
ros2 service call /exploration/save_map std_srvs/srv/Trigger # haritayı kaydet
```

**GCS ile tarayıcıdan izleme**:

```bash
ros2 launch gemstone_gcs gcs_bringup.launch.py
```

`http://localhost:8000` adresinde canlı harita, teleop ve keşif kontrolü
tek ekranda görünür.

<img src="/images/ika/gcs-screenshot.png" alt="GCS ekran görüntüsü" />

### 7.3. Ayarlar

Temel parametreler `gemstone_frontier_explorer/params/frontier_explorer.yaml`
dosyasında yer alır:

| Parametre | Varsayılan | Açıklama |
|---|---|---|
| `detect_period` | 1.0 sn | Tespit periyodu |
| `cluster_min_cells` | 8 | Minimum frontier boyutu |
| `w_size` | 1.0 | Boyut ağırlığı |
| `w_dist` | 2.0 | Mesafe ağırlığı |
| `commit_margin` | 0.05 m | Hedef değişimi önleme payı |
| `coverage_threshold` | 0.99 | Otomatik bitiş eşiği |
| `safety_distance` | 0.25 m | Güvenli mesafe |
